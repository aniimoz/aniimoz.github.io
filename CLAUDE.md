# CLAUDE.md

Guidance for Claude Code (and other AI assistants) when working in this repository.

## What this repo is

This is **`aniimoz.github.io`** — a **GitHub Pages user site**. Because the repo
name matches `<username>.github.io`, GitHub Pages serves it automatically at:

> https://aniimoz.github.io

It is a static website repo. There is no backend, no server, and no secrets.

## Deployment model (important)

- GitHub Pages builds and serves this site **from the root of the `main` branch**.
- **Every push to `main` goes live** — usually within a minute, with no separate
  build or deploy step. Treat `main` as production.
- `index.html` at the repo root is the site's entry point.
- The site is static files only (HTML / CSS / JS / images). Use **relative paths**
  for all assets so links work both locally and on the live domain.

### Optional config files (add only when needed)
- `CNAME` — a single line with a custom domain, if one is ever configured.
- `.nojekyll` — add an empty file by this name to **disable Jekyll processing**
  (needed if any file/folder starts with `_` and you are not using Jekyll).

## Aniimo data (crawled)

`assets/data/aniimo.json` — all aniimo (name, elements as data.js ids, roles,
region, form, stats, image URL, wiki URL), generated by
`.github/scripts/crawl-aniimo.mjs` from https://wiki.aniimo.com/vi (the Nuxt
pages embed JSON in `<script id="__NUXT_DATA__">`; no browser needed).

- Refresh it via GitHub **Actions → Crawl → Run workflow** (manual only). The
  workflow commits as `github-actions[bot]` only when data changed, then asks
  Pages to rebuild. Run locally: `node .github/scripts/crawl-aniimo.mjs`
  (`CRAWL_DETAILS=false` for list-only).
- The script refuses to overwrite the file if output looks broken (<50 entries,
  big drop vs. previous, >20% detail pages failing). Don't hand-edit the JSON.
- Content/images belong to the game publisher: credit the wiki, hotlink images
  from their CDN rather than copying them into the repo, keep crawling polite.

## Conventions

- Keep the site **static and dependency-light**; prefer plain HTML/CSS/JS unless
  the user explicitly asks for a framework or static-site generator.
- Test changes in a browser (locally via `python -m http.server`, or the live
  site) before/after pushing, since a push to `main` publishes immediately.
- Asset filenames: lowercase ASCII slugs, no spaces or Vietnamese diacritics.
